# 一击必杀 v0

低频、等、只打一枪。宏观门不开就不开新仓；日线没有偏向就看都不看；4H 要三条 EMA 同时转势，并且 ATR/收盘不高于自己近 20 根的 30 分位。仓位是全仓，名义本金 = 权益 × 杠杆，默认 20 倍。这一枪按账户算不到 1.618 倍风险，就继续等。

`dataprice backtest` 仍然只跑 TPO 价值区加当日 VWAP。一击必杀是 `dataprice sniper-backtest`。这里没有订单块、公允价值缺口、结构破坏那一套。

判断本身不连数据库。单测用造出来的 K 线和日频序列。

## 怎么跑

```shell
uv run pytest tests/test_sniper.py
make test
```

要扫已经入库的行情：

```shell
make up && make bootstrap
uv run dataprice backfill --symbol BTC-USDT --freq 60m --months 24
uv run dataprice macro-backfill --csv macro.csv
uv run dataprice sniper-backtest --symbol BTC-USDT --months 24 --fee-bps 5 --slippage-bps 2
```

60 分钟来自 OKX 的 `market.bars`。回测在内存里收成 UTC 对齐的 4H 和日线，缺一根就不合成那一根。库里的周期不用加 `4h`。

宏观 CSV 三列：`series_id,obs_date,close`。`series_id` 只认 `dxy`、`tips_10y`、`hy_oas`、`vix`，日期是工作日。

```csv
series_id,obs_date,close
dxy,2024-01-02,102.2
tips_10y,2024-01-02,1.74
hy_oas,2024-01-02,3.46
vix,2024-01-02,13.2
```

本机能访问 FRED 和 Yahoo 时，可以不准备文件：

```shell
uv run dataprice macro-backfill --fetch
```

10Y TIPS 实际利率是 FRED `DFII10`，HY OAS 是 FRED `BAMLH0A0HYM2`，DXY 是 Yahoo `DX-Y.NYB`，VIX 是 Yahoo `^VIX`。拉不到就改 CSV。`--fetch` 不是单测的一部分。

`macro-backfill` 写两张表：

| 表 | 内容 |
| --- | --- |
| `market.macro_daily` | 四条原始日频收盘 |
| `market.factor_macro_gate` | 合成门，`version=v0.1`，一行一个生效日 |

回测优先读原始日频再在进程里算 v0.1。原始表是空的、合成表里已有 v0.1，才直接用合成行。两张都空就停，并打印上面的回补命令。K 线多取回测起点前 120 天，宏观多取 400 天，用来暖日线 EMA、4H 的 EMA32、ATR 分位窗口和 63 日宏观中位数。成交只从 `--months` 窗口里记。

命令行只覆盖手续费和滑点。其余数字在 `sniper.evaluated_params()`。

## L0 宏观门 v0.1

θ = 0.55。四个因子等权，都是越高越紧：

| 因子 | 序列 | 公开来源 |
| --- | --- | --- |
| DXY | `dxy` | Yahoo `DX-Y.NYB` |
| 10Y TIPS 实际利率 | `tips_10y` | FRED `DFII10` |
| HY OAS | `hy_oas` | FRED `BAMLH0A0HYM2` |
| VIX | `vix` | Yahoo `^VIX` |

每个因子取截至观测日、含当天的最近 63 个收盘。最新点不高于这 63 个数的中位数，记 1，否则记 0。分数是四个数的平均。分数大于等于 0.55，GATE=1，否则 GATE=0。

四个 0/1 的分数只可能是 0、0.25、0.50、0.75、1。0.55 落在 0.50 和 0.75 中间，所以至少要三个因子不高于自己的中位数。少一个因子、点数不够 63、或某个因子相对观测日已经超过 10 个日历日没有新点，分数记空，门为 0。

时间：

- t 日的收盘在 t 日当天不能用。下一个工作日的会话才用它。
- 周六和周日不重新算。它们沿用周五已经生效的那扇门。周五生效的门来自周四或更早，不是周五收盘。
- 周一用周五收盘。周五到周一隔 3 个日历日，所以陈旧上限至少是 3，默认 10，用来盖住普通节假日。
- 周末如果出现在 CSV 里，直接拒绝。宏观日历只有工作日。

GATE=0 只挡住新开仓，不平掉已经持有的仓。

## L1 日线偏向

只做有偏向的日子。偏向用已经收完的 UTC 日，从下一个 UTC 日的 4H 才生效。当天的日线收盘不能给当天的 4H 开仓。

做多，两句都要：

- 结构：HH/HL，或者收盘高于前 20 根日线的最高价。HH/HL 用左右各 2 根的分形，右侧 2 根收完才确认。
- 收盘高于 EMA50。EMA 用收盘，前 50 根的均值做种子，之后系数 2/51。

做空对称：LH/LL，或收盘低于前 20 根日线的最低价，并且收盘低于 EMA50。两边同时成立就是平。EMA 还没长出来也是平，所以光突破 20 日高点、均线还没 50 根，仍然不做。

## L2 4H 进场

进场仍然只看 4H。日线偏向和 MacroGate θ = 0.55 照旧，两条都要对上方向、门也要开着，才看这根 4H。不再用刺破前高前低再收回。那是引诱，不是进场。

两条都要：

1. 三条 EMA 同时转势。周期是 6、12、32，都用收盘。种子是前 N 根的均值，之后系数 2/(N+1)，和日线 EMA50 同一套算法。
2. 波动低。ATR 长度 14。低波动看的是 ATR/收盘，不是 ATR 的绝对点数。

转势写死成和自己比，不和另外两条比：

- 做多：EMA6、EMA12、EMA32 每一条都严格高于自己 `ema_slope_bars` 根之前。默认 `ema_slope_bars = 1`，就是 `ema_t > ema_{t-1}`。不要求更早的几根也在涨，也不要求快线站在慢线上面。
- 做空：三条都严格低于自己的 t-1。
- 有一条走平（相等）就两边都不是。三条同时向上和同时向下不会发生在同一根上。

ATR 是 Wilder：

- 第一根没有上一根收盘，真实波幅就是最高价减最低价。后面用最高价减最低价、最高价对上一根收盘、最低价对上一根收盘，取最大的那个。
- 前 14 根真实波幅的平均放在第 14 根上做种子。之后 `ATR_t = (ATR_{t-1} × 13 + TR_t) / 14`。

低波动的窗口默认 20 根 4H，含信号这根。20 根大约 3.3 天，比 ATR 自己的 14 根稍长，用来描述眼前这一段，又不把更早的行情算进来。阈值是这 20 个 ATR/收盘的第 30 分位，不是中位数。位置用含端点的线性分位：`0.30 × (根数 - 1)`。20 根时位置是 5.7，取从小到大的第 6 个和第 7 个，再按 0.7 的权重偏向第 7 个。这和 NumPy 默认的 `percentile` 相同。最新的 ATR/收盘不高于这个数才通过。窗口含本根，所以一整段完全一样时最新值等于分位，仍然算低波动。用 ATR/收盘而不是 ATR，是为了价格水平变了以后阈值还在。30 分位比 50 分位更严，是这次实验收紧的结果。

最早能发出信号的一根，是 EMA32 已经能和上一根比、并且 ATR 分位窗口也凑满的那根。默认两边都落在第 33 根 4H（下标 32）。

进场价是这根收盘，再加不利滑点。止损放在这根影线之外。默认缓冲是 0，做多止损就是这根的最低价，做空就是最高价。从下一根才看是否碰到。开盘已经穿过止损，按开盘价成交，不再按更好的价格。同一根先碰止损就止损，不给目标。跳空穿过目标时仍按目标价成交。

同时只有一笔。持仓期间新的转势忽略。门关掉、偏向翻掉，都不把这笔平掉。数据结束时还敞着的仓，按最后一根收盘记 `end`。那是回测收尾，不是策略出场。最后一根上不开新仓。

## L3 全仓、价格 R 和账户 R

两个数分开记。仓位是全仓，不是拿权益的一个固定比例去挨止损。

| | 公式 |
| --- | --- |
| 名义本金 | 权益 × 杠杆。默认权益 10000，杠杆 20，名义 200000 |
| 数量 | 名义本金 / 进场成交价，再按数量精度四舍五入 |
| 1 账户 R | 这仓按止损成交价平掉时的现金亏损，含进场和止损两边的手续费。止损越近，1R 越小 |
| 价格风险 | 进场成交价到止损成交价的距离。两边都先加不利滑点 |
| 价格 R | 目标成交价到进场成交价的距离 / 价格风险。不含手续费 |
| 账户 R | 扣费后的盈亏 / 1 账户 R |

杠杆 20 就是仓位本身：每一笔的名义都是权益的 20 倍。它不是「先按 1% 定风险，再看所需杠杆超不超过 20」的上限。

目标价按账户 R = 1.618 来解。这是黄金分割的实验值，不是拿成交拟合的。手续费会让价格 R 略大于 1.618，因为有一部分波动用来付费。`min_account_rr` 的下限再放到 1，所以 1.618 可以通过；小于 1 仍然拒绝。调用方如果显式写成 3 或 10，目标就按那个数来解。

解不出来就跳过，记在结果的跳过笔数里：

- 止损不在进场的亏损一侧，或者按止损价平掉并没有现金亏损。
- 做空时解出来的目标价不是正数。
- 四舍五入之后怎么推都够不到账户 R。

默认每边手续费 5 个基点，每边不利滑点 2 个基点，和 TPO 回测的成本口径一样。没有资金费。这些默认值没有拿成交去拟合。

## 复现

```shell
uv run pytest tests/test_sniper.py
uv run dataprice sniper-backtest --help
```

`tests/test_sniper.py` 不连接 ClickHouse。它核对门的 θ、周末沿用、t-1、日线不把当天收盘用进当天 4H、三条 EMA 同时转、ATR/收盘不高于自己的 30 分位、止损在信号影线、全仓按杠杆定数量、账户 R 默认 1.618，以及 GATE=0 不平仓。
