# 日线辩论分配

三条猎手仍用各自训练时锁定的参数。这个分配器不重训，也不在 2026-03-01 及之后的留出样本上改门槛。它只在每根已经收盘的 UTC 日线上选一个模式，从该收盘用到下一根日线收盘。模式互斥，盘中不改。

决定只用收盘时已经知道的数：18 根已收盘 4 小时收益的 Kaufman 效率比、当时的 4 小时结构偏向，以及上一根 30 分钟收盘价两侧已经确认的等高/等低。

## 规则

`resolve(er, bias_4h, strong_range)` 不接收门槛参数。

1. 效率比 >= 0.25：4 小时结构偏多 → `long`；偏空 → `short`；中性或还没有结构 → `flat`。这时即使同时看得到区间，也不做网格。
2. 效率比 < 0.25：强区间 → `grid`；弱区间或没有区间 → `flat`。强区间指已经确认的 eqh 在收盘价上、eql 在收盘价下，并且按网格默认的 50 个基点放得下至少一档。放不进这一档、或者只能退回最近 48 根 30 分钟上下沿，都算弱区间。
3. 样本不够（效率比还是空）、偏向无法识别，或者同时出现多个可执行主张 → `flat`。

`long` 跑 `long_params()`：评估候选的多头，扫卖侧那根收盘要落在高低区间的 70% 以上，只做多。

`short` 跑 `short_regime_params()` 整条路径：多头仍是评估候选，不另加 CLV；空头还要最近 18 根已收盘 4 小时的效率比至少 0.25。这道空头过滤是路径自己的进场条件，不是把当天改成别的模式。

`grid` 跑震荡网格原本的档位、破位止损和库存浮亏停机。单独的 `--grid` 仍在效率比低于 0.25 时自己开关，并且会在没有等高/等低时退回上下沿。分配器里的网格日改由日线模式打开：当天效率比再站上 0.25 也不把这一日改回空仓。弱区间的日子分配器直接 `flat`，不把上下沿退路放出来。

模式切换的第一根 30 分钟，上一模式的持仓按开盘价平掉。同一模式跨过日线收盘时，持仓继续交给原路径的止损和止盈。

## 费用和样本

| 假设 | 取值 |
| --- | --- |
| 手续费 | 每边 5 bps |
| 滑点 | 每边往不利方向 2 bps |
| 每手 | 0.01 BTC |
| 训练 | 开仓 K 线的开盘时间早于 2026-03-01 |
| 留出 | 当天及之后，只评估，不调参 |

窗口就是命令里的 `--months`，终点是运行当时，不另加预热。窗口开头还凑不齐 18 根 4 小时收益的日子是 `flat`。

最大回撤按该桶已平仓盈亏、出场时间累计。网格账本另外给出自己的盯市回撤，那个数含库存浮盈浮亏。

## 复现

```shell
uv run pytest -q
uv run dataprice backtest --debate-daily --symbol BTC-USDT --months 24 --fee-bps 5 --slippage-bps 2
```

K 线要已经在 ClickHouse 里。没有的话先 `make up && make bootstrap`，再 `uv run dataprice backfill --symbol BTC-USDT --months 24`。`--debate-daily` 不能和 `--baseline`、`--flow`、`--regime`、`--trend-regime`、`--grid`、`--long`、`--short-regime`、`--buy-only` 一起用。
